# 可微 depth 读出训练接入（候选尚未定义）

本分支默认 `--depth_route baseline`，`render_pkg` 原样透传。`identity` 仅为接线控制，沿用原张量及梯度；`candidate` 当前明确报错，不是候选算法。未增加共面、分组或 teacher loss。`depth_target` 预留 expected/median/both 切换，但在候选实现前不改变任何深度。原默认 `depth_ratio=0`，训练使用 expected；正则自第7000次迭代起启用，PatchMatch 仅在 `lambda_multi_view_ncc>0` 时调用。只换 median 在这个默认配置下不会改变训练。

另有未接入训练的 `fixed_group_short_axis_ls_z` Torch 参考核：对**外部固定**的成员索引，给相机空间中心、短轴单位法向和非单位射线 `(x,y,1)`，算 `Σ(n·v)(n·m)/Σ(n·v)²`，输出相机 z。成员选择是离散输入；中心与法向仍保留 autograd。CPU float64 用有限差分核了中心 z 和法向旋转角梯度，并测了零分母拒绝。它没有分组、前层选择、整图接入、footprint 门或连续 `sample_depth` 一致性；不能把这项参考核当作已经能训练的候选。

`surface_group_reference.py` 是**单查询、accepted 列表已由宿主给出**时的更完整 Torch 小规模对照：输入相机空间中心、wxyz旋转、未AA尺度、原生alpha、相机射线与原深度。最多128个 accepted；正τ原值排序、原序号破同值；短轴尺度相对间隙>1e−3且最短/最长>1e−6，单位射线入射幅度≥.1；无向法向角≤10°（容差1e−6 rad），双方平面距离≤τ_i/f_min+τ_j/f_min（距离容差1e−7×max(1,|τ_i|,|τ_j|)）；成员自身交点须在2σ切向足迹内；不同几何至少2、组alpha≥.5。按前后顺序确定 complete-link 组；最前组任何门失败即原深度回退，绝不跳后组。保守起见，**任一**已接受成员无法定位或在自身足迹外也整条回退，不静默删掉后层成员。所有分支判定 detach，组内LS对中心/旋转/查询保梯度；尺度与alpha只影响离散分支，本项不要求它们的直接梯度。返回每条原因和门值。它尚未连接 `train.py`/CUDA/连续 `sample_depth`，门限是待验证的启发式实现约定，不是几何保证。

只读核验的远端 `main` 为 `8474727dd1c1f4fee77a3dc02a6cbc0b38075f21`；本分支起点 `a00c1e0` 的 train、renderer、loss、arguments、mesh 提取、DTU eval 与 `scripts/dtu.sh` 和该 main 一致。新增代码仅在独立 `research/depth-plugin-training-20261101` 工作树。用户给的原命令属于 main 基线，不能据研究分支名推断有不同原始损失。

短程对照需两份独立模型输出目录、相同完整 DTU 源、相同源码/宿主 CUDA 二进制、相同模型 PLY 或完整 checkpoint SHA 与相同参数；`ab_trace.jsonl` 记录初始参数 SHA、每步相机及邻近视角、损失、是否 step、按固定前2048个元素采样的参数/梯度/更新 RMS 和学习率。不同候选若影响随机数，A/B 专用相机选择器与全局随机数隔离；GPU 算子仍可能非逐位确定，应实核序列与初态。A/B 追踪要求起点至少第7000次迭代，且只在显式指定 `--ab_run_id` 时启用。日志路径以新建模式打开，避免覆写旧运行。

A/B 模式在 `prepare_output_and_logger` 与 `Scene` 首次写文件前检查输出目录必须不存在或为空；PLY 加载后按新成员数重置 `max_radii2D`，避免沿用 Scene 初始点云的长度。参数/梯度/step 诊断固定在**首次实际更新步**和此后指定间隔记录，不只在密化迭代采样。

在没有完整原训练 checkpoint 时，可以以**同一 PLY 加新 Adam**作 warm start。这不是原训练从7000步精确续训：Adam 动量、此前梯度统计和随机状态均不会从 PLY 恢复；两组必须各自记录 `optimizer_state=fresh_from_ply`。以下两臂只是透传等价性 smoke test，`identity` 绝不是新算法效果测试，命令需在核验真实源数据、GPU 环境和停机后才执行：

```bash
python train.py -s "$DTU/scan37" -m "$OUT/baseline" -r 2 --use_decoupled_appearance 3 \
  --warm_start_ply "$PLY" --warm_start_iteration 7000 --iterations 7101 \
  --depth_route baseline --ab_run_id baseline --ab_seed 0 --ab_log_interval 10 \
  --test_iterations 7101 --save_iterations 7101 --checkpoint_iterations 7101
python train.py -s "$DTU/scan37" -m "$OUT/identity" -r 2 --use_decoupled_appearance 3 \
  --warm_start_ply "$PLY" --warm_start_iteration 7000 --iterations 7101 \
  --depth_route identity --ab_run_id identity --ab_seed 0 --ab_log_interval 10 \
  --test_iterations 7101 --save_iterations 7101 --checkpoint_iterations 7101
```

上述从7001到7101共101次前向，原训练循环最后一次不作 optimizer.step，因此是100次更新。两个日志的初始参数 SHA 和逐迭代相机序列必须一致，先验证接线及梯度，再接入经审查的候选。正式候选还需验证 `[1,H,W]` CUDA float camera-z 深度、无效像素、梯度能到达 xyz/scale/rotation，并同预算比较。现阶段本地仅做 CPU 接线测试；没有运行上述 GPU 命令。

正式效果验收沿用项目15场景协议：`24 37 40 55 63 65 69 83 97 105 106 110 114 118 122`；每场 `train.py -s /root/autodl-tmp/DTU/scan${id} -r 2 --use_decoupled_appearance 3`，随后 `mesh_extract.py -m <独立输出>` 与 `evaluate_dtu_mesh.py -m <独立输出> --DTU /root/autodl-tmp/DTU_MVS_Data`。两臂必须用彼此独立的新输出目录，不能写入原 `/root/autodl-tmp/GauDepth/outtest/scan${id}`。此协议尚未执行，也不能由离线扫描代理替代。

`dtu_eval/eval.py` 报告 `mean_d2s`（mask内重建点至GT扫描点）、`mean_s2d`（地面上GT扫描点至重建点）及二者平均 `overall`。它在下采样前使用未设种子的 `default_rng().shuffle`，正式评价需保留逐次结果并量化随机波动，不能把一次微小差异直接归因于插件。

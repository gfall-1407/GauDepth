## 真实 32 射线最小 capture

父线程统一协调 G5 采集。需一个自包含 manifest，记录实例完整 ID、hostname、Git remote/branch/HEAD/dirty、原模型和 cfg 的绝对路径及 SHA256、运行时 rasterizer 源码提交与已安装二进制 SHA256/构建来源、filter3D 与 opacity 规则、图像与相机坐标约定、原始射线与模型所有输入的 SHA256。不能只靠 Git HEAD 推断扩展版本。

每条固定 scan110 原 7k 的 32 个 pixel：参考 view ID、整数像素、GT mask/深度、宿主 Expected 与法向邻域深度、完整 native accepted 顺序的原 PLY 行 ID、`mu`、短轴世界法向及其来源、旋转/scale/opacity、原 `alpha`、前缀 `T`、Gaussian 射线 footprint、过滤原因与原分辨率。保存原 PLY 头和文件 SHA；以 ID 索引回读 PLY 字段核验，不复用旧 ID 映射作为证明。

固定两张分支选择见证图像、原训练使用邻视图、额外一张 heldout：每张的原图像字节与 SHA、mask、内参、外参、resize/crop/颜色空间、view ID，以及参考像素法向损失需要的邻域。见证图与 heldout 不重用。patch 边界、遮挡和无法投影要标记为 invalid。

真实诊断在不更新模型的同一起点运行：完整 32 条记录原深度、候选深度、valid/reason、原训练损失分母；同 optimizer 预条件下比较 Expected 与候选的真实参数更新方向，并用中央差分测量 heldout 原图 patch 误差方向变化，记录 RGB 变化。只有完整 32 集合 heldout patch 误差方向均值改善、valid 子集中位改善、且 valid≥8/32 才考虑密集 CUDA。第一步 Adam 必须使用真实参数梯度和状态，不能以 RMS 冒充更新。固定门槛不扫 tau 或阈值。
